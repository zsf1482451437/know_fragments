案例必须具体说明：

- 架构：浏览器 → CDN/Web 应用 → BFF → 业务服务/任务服务 → 数据库、缓存和消息系统。

- [ ] **Step 3: 完成移动电商 App 案例**

案例必须具体说明：

- 业务：商品浏览、购物车、结算、支付、订单和推送。
- 架构：App → API Gateway/BFF → 商品、购物车、库存、订单、支付服务 → 数据库、缓存、消息系统和第三方支付。
- 权威源：价格和库存以服务端为准；本地只保存展示缓存和未提交意图。
- 交易：结算重新校验、订单幂等创建、支付回调验签、状态机和补偿。
- 弱网：超时、退避重试、请求去重、离线读取和恢复提示。
- 发布：商店审核、分阶段灰度、最低兼容版本、强制/推荐升级。
- 指标：崩溃率、ANR、启动耗时、结算成功率、支付成功率和库存冲突率。

使用 Mermaid `sequenceDiagram` 绘制“结算 → 创建订单 → 支付 → 回调确认”的关键链路。

- [ ] **Step 4: 完成跨平台企业客户端案例**

案例必须具体说明：

- 业务：跨平台、本地文件处理、离线工作、后台同步和企业分发。
- 取舍：按团队 Web 能力、包体、内存、安全边界和系统集成要求比较 Electron/Tauri。
- 进程：渲染层不直接访问系统能力；通过白名单 IPC 调用主进程/命令层。
- 数据：SQLite 是离线工作集，云端是协作权威源；记录同步状态、版本和冲突。
- 安全：IPC 参数校验、路径规范化、文件范围限制、凭据安全存储和更新包验签。
- 恢复：原子写入、数据库迁移备份、断点续传、更新失败回滚和崩溃恢复。
- 指标：启动耗时、崩溃率、同步成功率、冲突率、更新成功率和资源占用。

使用 Mermaid `flowchart TB` 绘制渲染进程、主进程/命令层、本地存储、同步服务和云端之间的边界。
