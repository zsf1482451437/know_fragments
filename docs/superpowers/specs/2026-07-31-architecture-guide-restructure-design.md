# 三端项目架构指南重构设计

## 目标

将 `简历相关/架构.md` 从平台百科说明重构为可用于项目启动、架构评审、开发交付和长期维护的执行指南。

## 适用范围

- Web：官网、SaaS 后台、商城和 AI Web 应用。
- App：原生、React Native、Flutter 和 Hybrid 应用。
- 桌面：Electron、Tauri、Qt 和原生桌面客户端。

三端保持同等深度，共享统一生命周期，差异通过平台 Playbook 和完整案例展开。

## 总体结构

### 1. 使用方式与原则

- 架构从业务目标和约束出发。
- 每个决策必须包含适用条件、代价和验证方式。
- 先定义边界和非功能需求，再选择技术。
- 关键链路必须可测试、可观测、可回滚。

### 2. 通用生命周期

每个阶段统一采用以下结构：

1. 目标。
2. 关键决策。
3. 必要产物。
4. 常见风险。
5. 退出门禁。

阶段包括：

1. 业务目标与约束。
2. 需求边界与非功能需求。
3. 架构和数据设计。
4. 工程基线建设。
5. 功能开发与联调。
6. 质量验证。
7. 发布、灰度与回滚。
8. 可观测性和长期演进。

### 3. 三端 Playbook

#### Web

覆盖渲染模式、路由、状态、BFF、权限、缓存、SEO、Web 安全、部署与 Web Vitals。

#### App

覆盖跨端与原生边界、导航、权限、离线数据、弱网、端能力、版本兼容、灰度、崩溃和性能监控。

#### 桌面

覆盖框架选型、主进程与渲染进程、IPC 安全、本地文件、SQLite、离线同步、安装包、自动更新和崩溃恢复。

### 4. 完整架构案例

#### SaaS 运营后台

包含 RBAC、数据范围、表格表单、批量任务、审计、BFF、测试、部署和监控。

#### 移动电商 App

包含商品、购物车、结算、支付、库存权威源、离线缓存、弱网处理、推送、灰度和版本兼容。

#### 跨平台企业客户端

包含 Electron/Tauri 选择、进程边界、IPC 白名单、本地 SQLite、云同步、自动更新和故障恢复。

每个案例必须说明：

1. 业务目标和约束。
2. 架构图或文本链路。
3. 模块职责。
4. 核心数据流。
5. 关键取舍。
6. 异常和安全设计。
7. 测试与发布。
8. 监控指标。
9. 演进路径。

### 5. 可复用模板

- 一页式架构方案模板。
- 非功能需求清单。
- 架构评审清单。
- 发布前门禁。
- 上线后复盘模板。

## 内容处理规则

- 删除网站、App、桌面生命周期中的重复通用描述。
- 合并重复的业务先行、平台约束、工程规范、质量保障和演进策略。
- 技术选型表改为“何时选择、主要代价、验证方式”。
- 保留必要概念，但不写成工具百科。
- 不将任何技术描述为普遍最佳方案。
- 所有安全、数据一致性和权限建议明确职责边界。

## 验收标准

- 文档具有清晰目录和单一主线。
- 八个生命周期阶段均包含目标、决策、产物、风险和退出门禁。
- Web、App、桌面 Playbook 深度一致。
- 三个完整案例均覆盖九项案例结构。
- 五类模板完整可复制使用。
- 删除明显重复章节和重复结论。
- Markdown 标题层级、表格和代码块格式正确。

## 测试影响

本次仅重构 Markdown 文档，不涉及业务代码。单元测试和 E2E 不适用；使用标题结构、必备章节、代码块闭合和 `git diff --check` 完成验证。
